# Amazon S3 (Simple Storage Service)

## Overview
Object storage with virtually unlimited scalability. 11 9's (99.999999999%) durability.

## Storage Classes

| Class | Use Case | Availability | Min Storage |
|-------|----------|------|-------------|
| S3 Standard | Frequently accessed | 99.99% | None |
| S3 Standard-IA | Infrequent access | 99.9% | 30 days |
| S3 One Zone-IA | Non-critical infrequent | 99.5% | 30 days |
| S3 Glacier Instant | Archive, ms retrieval | 99.9% | 90 days |
| S3 Glacier Flexible | Archive, min-hours retrieval | 99.99% | 90 days |
| S3 Glacier Deep Archive | Long-term archive | 99.99% | 180 days |
| S3 Intelligent-Tiering | Unknown/changing access | 99.9% | None |

## Key Features

### Versioning
- Protects against accidental deletes
- Each version is a full object
- Delete marker for "deleted" objects
- MFA Delete for extra protection

### Replication
- **CRR (Cross-Region Replication)** — DR, compliance, lower latency
- **SRR (Same-Region Replication)** — log aggregation, live replication between accounts
- Requires versioning enabled on source and destination
- Not retroactive (only new objects after enabling)

### Lifecycle Policies
- Transition actions (move between storage classes)
- Expiration actions (delete after X days)
- Can apply to current/previous versions

### Event Notifications
- Triggers on object events (put, delete, copy)
- Destinations: SNS, SQS, Lambda, EventBridge

### S3 Object Lock
- WORM model (Write Once Read Many)
- **Governance mode** — special permissions can override
- **Compliance mode** — no one can override (not even root)
- Legal Hold — prevents deletion indefinitely

## Performance
- 3,500 PUT/COPY/POST/DELETE per prefix per second
- 5,500 GET/HEAD per prefix per second
- **Multipart upload** — recommended for >100MB, required for >5GB
- **S3 Transfer Acceleration** — uses CloudFront edge locations
- **S3 Byte-Range Fetches** — parallelize downloads

## Access Control
- Bucket policies (JSON, resource-based)
- ACLs (legacy, avoid)
- Block Public Access settings
- Access Points (simplify access for large datasets)
- VPC Gateway Endpoint (private access)

## Exam Tips
- S3 is object storage (not block or file)
- Max object size: 5TB (multipart for >5GB)
- Strong read-after-write consistency
- Use pre-signed URLs for temporary access
- S3 Select / Glacier Select for server-side filtering

## SAA Decision Addendum

### Choose This When
- **Versioning**: protect against accidental overwrite/delete and enable replication.
- **CRR**: meet compliance, DR, or low-latency access requirements in another Region.
- **SRR**: aggregate logs, replicate between accounts, or keep copies in the same Region.
- **Object Lock**: WORM retention or legal hold is required.
- **Pre-signed URL**: temporary direct access to a private object is needed without making the bucket public.
- **CloudFront + OAC**: private S3 content must be delivered globally over HTTPS with caching.

### Exam Traps
- S3 bucket names are globally unique, but buckets live in a specific Region.
- Replication requires versioning and is not retroactive by default.
- Glacier classes are not for frequently accessed millisecond workloads unless the class says Instant Retrieval.
- Multipart upload improves reliability/performance but is not a cost optimization by itself.
- S3 is flat object storage; "folders" are key prefixes.
